1. 처음 시작하기

docs/github-first-steps.md

GitHub·Git 처음 사용하는 팀원 안내 (Windows)

1. 무엇을 설치하나요?

  • GitHub는 브라우저로 사용하는 공동 저장소 서비스입니다.
  • Git은 PC에서 변경 이력을 관리하는 프로그램입니다.
  • 이 안내는 Git 명령을 사용하며 GitHub Desktop은 필수 설치가 아닙니다.
  • D는 문서 열람과 Figma 작업만 한다면 Git·Python을 설치하지 않아도 됩니다.

2. 계정·초대 확인

  • 브라우저에서 https://github.com 접속 → 계정이 없으면 Sign up, 있으면 Sign in → 본인 계정으로 로그인합니다.
  • 팀장이 보낸 저장소 초대를 수락한 뒤 https://github.com/dbco0711/Re 를 엽니다.
  • 404가 뜨면 계정·초대 수락부터 확인합니다.
  • 비밀번호·인증 코드·토큰은 공유하지 않습니다.

3. Git 설치 확인과 설치

Windows 시작 버튼에서 PowerShell을 검색해 실행합니다. 다음 한 줄을 붙여넣고 Enter를 누릅니다. 코드 블록의 ```나 PS로 시작하는 안내 문구는 입력하지 않습니다.

git --version
  • 버전이 나오면 설치를 건너뜁니다.
  • 명령을 찾을 수 없다고 나오면 https://git-scm.com/install/windows 에서 PC 아키텍처에 맞는 Setup 설치 파일을 받습니다(설정 → 시스템 → 정보 → 시스템 종류로 x64/ARM64 확인). 다운로드한 설치 파일을 실행하고 설치 마법사의 안내를 따릅니다.
  • 모르는 선택지가 있으면 기본값을 유지하되 PATH 항목은 명령 프롬프트와 다른 프로그램에서 Git을 사용할 수 있는 선택을 유지합니다.
  • 설치 후 PowerShell을 닫았다가 다시 열어 git --version을 재확인합니다.

4. 프로젝트를 내 PC에 받기 (clone)

탐색기에서 본인이 작업할 부모 폴더를 새로 만들거나 선택합니다. 팀장의 PC 경로를 따라 만들 필요는 없습니다. 그 폴더 주소 표시줄을 클릭해 powershell을 입력하고 Enter를 누릅니다.

Get-Location
git clone https://github.com/dbco0711/Re.git
cd Re
git status
  • 한 줄씩 실행합니다.
  • Get-Location은 현재 위치를 확인합니다.
  • clone은 그 안에 Re 폴더를 만들고 내려받습니다.
  • cd Re는 받은 폴더로 들어갑니다.
  • status는 현재 상태를 보여줍니다.
  • 인증 창이 나타나면 본인 GitHub 계정으로 브라우저 인증합니다.
  • 비밀번호를 명령에 붙이지 않습니다.
  • Re 폴더가 이미 있다는 오류가 나면 삭제하거나 다시 clone하지 말고 기존 폴더의 출처를 B에게 확인합니다.
  • GitHub Code → Download ZIP은 읽기용으로 가능하지만 Git 이력이 없으므로 협업용 clone 대신 사용하지 않습니다.

5. 파일 읽기

Re에서 자료 목차를 엽니다. GitHub에서는 Code 탭에서 파일을 클릭하면 문서가 표시됩니다. PC에서는 메모장 또는 이미 설치된 코드 편집기로 엽니다. D는 GitHub에서 바로 읽어도 됩니다.

GitHub가 처음이라면

설치·계정·clone 상세 안내를 읽습니다. 전체 문서는 한글 자료 목차에서 찾고, 제출할 때는 브랜치·PR 실습을 따릅니다.

서버 화면이 안 열릴 때

  • 서버 실행 명령을 입력한 PowerShell 창을 켜 둔 상태에서 브라우저를 엽니다.
  • Uvicorn running 메시지가 나오기 전에는 서버가 준비되지 않은 것입니다.
  • Ctrl+C 또는 창 닫기로 종료하면 두 주소 모두 열리지 않습니다.
  • 각자의 127.0.0.1은 각자의 PC이며 팀장 서버로 자동 연결되지 않습니다.
  • 접속 실패 시 서버 터미널의 오류를 먼저 전달하고 방화벽을 무작정 끄지 않습니다.

2. MVP 사양서

docs/mvp-spec.md

MVP 사양 v0.1 초안

목적과 범위

동의한 사용자의 최대 30초 메모를 경로·시각에 연결하고 같은 방향의 연속 도로 구간 재방문 시 회상 카드를 제공합니다.

순서동작완료 기준
1주행 시작·종료trip_id 발급, 실제/재생 출처 표시, GPS 순서 유지
2메모 동의·녹음동의 전 녹음 없음, 시작·중지 명시, 30초 자동 종료
3처리전사·요약·목적·키워드 반환, 처리 출처와 실패 표시
4저장같은 trip의 기기 시각으로 메모 구간 연결, 재요청 시 중복 방지
5재방문 검색현재 trip 제외, 방향·연속성·중복 길이 판단
6회상 카드운전 중 짧고 중립적인 안내, 긴 원문은 정차 후 명시적 조작
7관리정차 후 수정·삭제·동의 철회, 철회 즉시 신규 녹음·처리 중단

동의 철회 시 연결된 음성·전사·요약·위치 연결과 대기 작업을 제거하는 흐름을 설계합니다. 실제 제공자 보관 정책은 선정 후 별도 확인합니다. 원음 보관 기간은 미정이며 정하기 전 실제 음성 수집을 시작하지 않습니다.

제외

상시 녹음, 다중 계정·공유, 차량 하드웨어 제어, 도로망 고정밀 매칭, 상용 운영, 고급 감정 분석. TTS·타임라인·PostGIS는 후속 후보입니다.

매칭 검증

  • 합성 경로로 같은 방향 중복, 역방향, 단일 근접점, 정지 중 흔들림, GPS 누락, 현재 trip 제외를 확인합니다.
  • 허용 거리·방향 차이·최소 중복 길이·연속 점수는 B가 시험 후 결정합니다.
  • 샘플은 알고리즘 성공 증거가 아닙니다.

미결정

AI 제공자·비용, 원음 보관, 매칭 임계값, SDK 권한·버전 조합, 실제 차량 검증, 제출 일정·조건. 공식 자료 재확인 전 확정하지 않습니다.

3. 데이터·API 계약 초안

docs/data-contract.md

공통 데이터 계약 v0.1 초안

shared/examples는 전부 fixture입니다. 서버 구현 전 합의용이며 실제 SDK 데이터가 아닙니다.

필드규칙
schema_version문자열 0.1, 변경 시 A·B·C 합의
trip_id / memo_id비어 있지 않은 문자열, 실제 구현은 UUID 예정
source경로는 replay 또는 real_gps, 샘플은 replay
processing_sourcefixture, manual, actual_api; actual_api는 provider·model도 기록
started_at / recorded_atUTC ISO 8601, Z 표기
elapsed_mstrip 시작 후 단조 증가 시간, 0 이상 정수
seqtrip 내 0부터 연속 증가, 중복 재전송은 동일 내용만 허용
lat / lonWGS84 십진도, 각각 -90~90 / -180~180
accuracy_m0 이상 미터; 없으면 null, 0으로 추정하지 않음
  • trip.started_at과 GPS elapsed_ms·메모 start_elapsed_ms/end_elapsed_ms는 같은 기기의 같은 trip 기준입니다.
  • 메모 길이는 0초 초과 30초 이하이며 trip 범위를 벗어나면 연결하지 않습니다.
  • 서버 수신 시각으로 좌표를 추정하지 않습니다.
  • heading이 없거나 정지한 경우 방향을 확정하지 않습니다.
  • 끊긴 구간을 무조건 연결하지 않습니다.
  • AI 입력은 memo_id와 전사 또는 향후 음성 참조입니다.
  • 결과는 transcript, summary, travel_purpose(불명확하면 null), keywords(배열), processing_source를 포함합니다.
  • 실패를 빈 성공 응답으로 바꾸지 않습니다.
  • manual 전사와 fixture는 actual_api가 아닙니다.

card.json은 UI 연결용입니다. 녹음·GPS·AI 결과 또는 재방문 판정의 증거가 아닙니다. 실제 API 연결 전 타입·필수 여부를 서버 모델과 맞추고 버전을 확정합니다.

  • 삭제·철회 도중 완료된 AI 결과가 다시 저장되지 않도록 취소 상태를 확인해야 합니다.
  • 현재 서버는 인증 없는 PC 내부 연결 확인용이므로 외부 노출하지 않습니다.

예정 오류: 400 순서·시간 충돌, 404 미존재, 409 동일 client ID에 다른 내용, 422 입력 검증, 503 처리 제공자 장애. error.json은 목표 형식이며 현재 FastAPI 기본 오류를 변경한 것은 아닙니다.

A↔B는 Python 모듈 단위로 우선 연결합니다. 별도 AI HTTP 서버는 요구하지 않습니다. 구현 전 B가 요청·응답 모델과 오류 형식을 확정하고 C에게 전달합니다.

docs/role-guide.md

역할별 시작과 인수 기준

A 오태경

1
START-HERE의 Python 환경 확인.
2
shared/examples/ai-result.json을 읽고 fixture 결과 생성 함수 준비.
3
다음 담당 폴더 backend/ai에서 작업. 함수 계약 초안은 analyze_memo 입력 memo_id·transcript, 출력 AI 결과 dict. 실제 음성 입력 방식은 B와 합의.
4
정상·빈 입력·불명확한 목적·처리 실패 예시를 전달. 이후 제공자 선정 후 실제 STT·LLM 연결.

완료 증거: 실행 명령, 실제 출력, 출처, 실패 예시. API 키는 공유하지 않음.

B 김유채

  • 현재 서버·가상환경은 로컬 검증 완료. 다음은 데이터 모델·SQLite 저장·API 입력 검증과 매칭 시험 설계입니다.
  • backend/database, matching, routes, services는 시작 시 생성합니다.
  • A·C와 v0.1 필드를 합의하고 변경 기록을 남깁니다.

5. 협업·브랜치·PR

docs/collaboration.md

협업 규칙

  • main은 통합 기준입니다.
  • 작업 전 git status로 미저장 변경을 확인하고, 깨끗한 main에서 git pull --ff-only 후 역할별 브랜치를 만듭니다.
  • 충돌 시 강제 덮어쓰기·reset을 하지 말고 B와 확인합니다.

예: git switch -c a/fixture-result, b/trip-storage, c/home-screen, d/design-notes. Codex가 만드는 브랜치는 codex/ 접두사를 사용합니다.

  • 변경 파일을 git add 경로로 선택하고 git diff --cached로 확인 후 commit·push합니다.
  • GitHub에서 Pull request를 만들고 B가 검토·통합합니다.
  • PR에는 변경 목적, 실제 실행 결과, 미검증 항목을 씁니다.
  • main 강제 push는 하지 않습니다.
  • 담당: A backend/ai, B backend의 나머지·데이터 계약, C android-app, D design. shared/examples와 공통 사양 변경은 A·B·C가 먼저 합의합니다.
  • 담당은 협업 경계이며 GitHub 접근 권한 제한을 설정했다는 뜻은 아닙니다.
  • 실제 키·음성·동선·DB·빌드·서명 키는 올리지 않습니다.
  • JSON이라고 자동으로 안전한 것은 아닙니다.
  • 합성 자료만 shared/examples와 test-data/synthetic에 넣습니다.
  • 팀원 메시지·초대·배포는 별도 사용자 작업입니다.
docs/git-practice.md

첫 작업 제출 실습 (A·B·C, Git 명령 사용)

  • commit은 PC 안의 저장 지점, push는 GitHub 업로드, pull은 팀 변경 내려받기, branch는 독립 작업 줄기, PR은 main에 합쳐 달라는 검토 요청입니다.
  • 파일을 저장하는 것만으로 GitHub에 올라가지 않습니다.

1. 시작 전

PowerShell에서 clone한 Re 폴더로 들어가 실행합니다.

git status

변경이 있으면 다음 명령을 진행하기 전에 B에게 확인합니다. 깨끗하면:

git switch main
git pull --ff-only
git switch -c a/first-fixture

마지막 이름은 A 예시입니다. C는 c/first-screen처럼 자신의 작업 이름을 사용합니다. 기존 브랜치가 있다고 나오면 -c로 재생성하지 말고 B에게 확인합니다.

2. 작성자 확인 (첫 commit 전)

git config --get user.name
git config --get user.email
  • 값이 없거나 본인이 아니면 아래의 예시를 본인 값으로 바꿔 실행합니다.
  • --global을 쓰지 않으므로 이 프로젝트에만 적용됩니다.
  • 공개하고 싶지 않은 이메일은 GitHub Settings → Emails에서 제공하는 본인의 noreply 주소를 사용합니다.
git config user.name "본인 이름"
git config user.email "본인의 GitHub용 이메일"

예시 문자열 그대로 저장하지 않습니다.

3. 파일 저장 후 확인·commit

아래 경로는 A가 실제로 해당 파일을 만들었을 때의 예시입니다. 파일이 없으면 그대로 실행하지 말고 본인이 수정한 파일 경로로 바꿉니다.

git status
git diff
git add backend/ai/example.py
git diff --cached
git commit -m "Add fixture AI result example"
  • 새 파일 내용은 git diff에 안 보일 수 있어 git diff --cached에서 반드시 확인합니다.
  • 키·음성·실제 위치·.env가 보이면 commit하지 말고 B에게 확인합니다.
  • nothing to commit은 저장하거나 선택한 변경이 없는 상태입니다.

4. GitHub에 작업 브랜치 올리기

git push -u origin a/first-fixture

본인의 브랜치 이름으로 바꿉니다. GitHub 인증은 본인 계정으로 진행합니다. main에 직접 push하거나 --force를 붙이지 않습니다.

5. PR 만들기

  • GitHub Re 저장소 → Pull requests → New pull request → base: main, compare: 본인 브랜치 → 변경 파일 확인 → Create pull request. 제목은 변경 목적, 본문은 바뀐 내용·실행한 명령과 결과·미검증 항목을 씁니다.
  • B 검토 전 임의로 Merge하지 않습니다.

6. 충돌·거절 시

  • push rejected, merge conflict, pull 실패가 나면 강제 명령을 사용하지 않습니다.
  • 실행한 명령·오류를 인증정보 없이 B에게 전달합니다.
  • PR이 합쳐진 뒤 새 작업은 깨끗한 main에서 pull하고 새 브랜치를 만듭니다.
  • 다른 작업 중 변경을 잃을 수 있으니 reset·clean을 임의로 실행하지 않습니다.

D는 이 실습이 필수가 아닙니다. Figma 링크·동작표를 B·C에게 전달하는 방식으로 시작합니다.

# B 백엔드 구현·검증 현황 (2026-11-07)

로컬 브랜치 codex/b-backend. GitHub 미업로드. 실제 음성·유료 AI·외부 배포 없음.

## 구현
- trip·GPS 저장·조회, 동일 요청 재전송, 순서·좌표·UTC 검증.
- 메모 동의·최대 30초·GPS 시간 구간 연결·저장·조회·수정·삭제.
- 철회 시 메모·GPS 삭제, 추가 수집 거부, 삭제·철회 후 늦은 AI 결과 거부.
- PUT /v1/memos/{memo_id}/analysis: A 결과 수신. fixture/manual/actual_api 구분, actual_api 제공자·모델 필수. 실제 제공자를 호출하거나 결과의 진위를 인증하는 기능은 아님.
- POST /v1/memories/search: current_trip_id, limit(기본5/최대20). 저장된 현재 GPS 최근200점, 최근 메모 후보50개 검색. 현재 trip·미래 메모·철회 제외, replay와 real_gps 혼합 제외.
- 회상 카드는 일반 안내·시각·출처·매칭 수치만 제공. 운전 중 원문·요약 자동 노출 없음. 상세 GET은 C가 정차 후 명시적 조작에서만 호출해야 함.

## 매칭 기준 (실제 주행 미보정)
WGS84 두 점 거리·방향 계산 → 약10m 간격 재표본 → 순서가 이어지는 같은 방향 구간 비교.
거리25m, 방향차35도, 중복100m 이상. 마지막 현재 이동 구간까지 일치해야 하며 이미 이탈한 옛 구간만으로 표시하지 않음.
5m 미만 이동·15초 초과 GPS 간격·seq 누락·30m 초과 또는 미제공 정확도·60m/s 초과 속도 구간은 연결하지 않음. 후보별 최대3000 표본 초과 시 409로 작은 경로 창 요청 필요.
메모 실제 시간 안의 측정점만 매칭하므로 짧거나 점이 적은 메모는 검색되지 않을 수 있음. 같은 근처의 평행도로·복잡한 교차로·다른 표본 간격·GPS 튐은 실제 자료로 추가 검증 필요. 도로망 Map Matching이나 정밀 위치 보간이 아님.

## 남은 실제 통합
A의 실제 STT·LLM 실행과 실패·철회 연동, C의 GPS·녹음·정차 UI·Emulator 연결, 실제 주행 임계값 보정. 인증 없는 PC 내부 MVP이므로 인터넷 공개 불가. 원음·외부 AI 보관 삭제는 아직 데이터가 없어 미검증. 멀티 계정·운영 보안·대량 조회 최적화는 범위 밖.
