# 역할별 후속 작업표

일정 날짜 대신 완료 기준으로 다음 단계로 넘어갑니다. 아래 항목은 개발 계획이며 완료 보고가 아닙니다. 먼저 끝난 담당은 다른 담당을 기다리는 동안 샘플·오류 처리·문서 보완을 진행합니다.

## A 오태경 — AI·음성

| 단계 | 할 일 | 제출물·완료 기준 | 연결·조건 |
|---|---|---|---|
| 1 · 첫 작업 | 공통 Python 환경 준비, fixture 결과 생성 함수와 정상·실패 JSON 작성 | 함수·실행 명령·출력·fixture 표시를 B에게 전달 | B와 입력·출력 필드 합의 후 2단계 |
| 2 · 전사 입력 처리 | manual 전사로 요약·목적·키워드 처리 흐름 구성, 빈 입력·불명확한 목적 처리 | manual/fixture 구분, 목적 불명확 시 null, 오류 예시 | 실제 제공자 선정 전에는 manual로 B와 통합 가능 |
| 3 · 실제 STT·LLM | B와 사용 가능 여부·비용·보관 정책 확인 후 제공자 선정, 동의한 짧은 음성 처리 | 실제 제공자·모델·처리 출처, 실패·시간초과 처리, 실제 실행 결과 | 유료 API 연결은 별도 승인 후 진행; 준비 안 되면 manual 유지 |
| 4 · B 통합 | B의 메모 ID로 호출·결과 연결, 중복 요청·취소·철회 후 결과 반영 차단 협의 | B와 정상·빈 음성·실패·철회 사례 결과 공유 | B가 저장·작업 상태를 준비하면 연결 |
| 5 · 시연 준비 | 합의한 합성/동의 데이터로 품질 확인, 알려진 한계 정리 | 실제 처리와 대체 처리 목록·시연용 결과를 B·D에게 전달 | 실패 시연에서 성공으로 위장하지 않음 |

## 공통 연결 순서

1. A·B·C: JSON 필드 합의 / D·C: 화면·동작 합의.
2. C는 fixture 화면, A는 fixture/manual 결과, B는 저장 API를 병렬로 준비.
3. B·C는 합성 경로 저장·검색·카드를 연결. A 실제 API가 준비되면 교체.
4. 실제 GPS·실제 STT·SDK 검증은 각자 수행하고 결과를 공유.
5. B가 통합 확인한 동작으로 D·C가 시연 영상·APK를 준비.
